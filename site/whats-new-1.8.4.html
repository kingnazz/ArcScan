ArcScan 1.8.4

What's new in ArcScan 1.8.4

ArcScan can travel with you. 1.8.4 adds a Windows Portable edition: unzip it to a folder or a USB drive and run it. It is a different build, not the installer’s executable in a ZIP. ArcScan-owned persistent data stays in an ArcScanData folder beside the app: the scan history, the inventory, the names, the notes, and the settings too. That copy of ArcScan carries its own memory wherever you put it.

Portable, and meant literally.

Plenty of tools call a ZIP portable while still writing their database into the user’s application data. Move the folder and the history stays behind; take it to another machine and it starts empty. This is not that.

One folder, everything in it

The database and the settings both travel.

The portable build is compiled as a portable build. It works out which folder it is running from, taken from the executable itself and never from whatever directory happened to launch it, and keeps two things in an ArcScanData folder there: the SQLite database, and the application profile that holds your theme, recent targets, column layout and discovery settings.

Isolating the database alone would have been the easy half and the wrong answer. A portable ArcScan whose preferences came from an installed copy is not portable; it just has a portable database.

Settings tells you where. The About section names the edition, the architecture of the build you are actually running, and the exact data path, with a button to copy it. If you are about to move the folder, that is the folder to take.

Installer or portable?

For a computer you use regularly, the installer. Portable is for the cases the installer is bad at: a machine you do not want to install anything on, a USB stick in a technician’s pocket, a look at a network you are visiting once.

Where the data lives.

The folder

Extract the ZIP and you have ArcScan.exe and a README. Run it once and ArcScanData appears beside them, holding arcscan.db, a WebView profile directory and a lock file that exists only while ArcScan is running.

Moving it

Close ArcScan and move the whole folder: another drive, a USB stick, another computer. Nothing inside the database depends on where it was. Backing up is the same operation: close ArcScan, copy the folder.

Removing it

Close ArcScan and delete the folder. There is no installer to run, no service, no registry setting for ArcScan’s own state, and no Start-menu entry left behind.

Said precisely

ArcScan-owned persistent data stays in ArcScanData. That is the claim, and it is the whole claim. Windows itself, and the Microsoft Edge WebView2 Runtime, keep ordinary records of programs that have run on a machine, and no application controls those. ArcScan does not write its database, its preferences or its cache anywhere else.

Two copies, two histories.

An installed ArcScan and a portable one can sit on the same computer without either knowing about the other, and so can two portable folders.

Nothing shared

Separate databases and separate application profiles. Neither reads the other’s scan history, device names, notes, statuses or settings.

Nothing merged

A portable copy starts with its own empty history rather than importing the installed one, and the installed app never goes looking for a portable folder. Nothing is merged in either direction, automatically or silently.

One at a time per folder

Two copies of ArcScan running out of the same ArcScanData would corrupt it, so the second one says so and stops. A second copy from a different folder is fine, and so is running portable and installed together.

Updating a portable copy.

Portable ArcScan still tells you when a newer version exists, because an out-of-date network tool is a problem in itself, but it does not install it. The portable build does not contain the installer updater at all.

  1. Close ArcScan

    Nothing can be replaced safely while it is running, and the portable folder is where the running copy keeps its data.

  2. Download the newer ZIP

    The Windows Portable ZIP for your architecture, x64 or ARM64, from the release page.

  3. Replace the application files

    Extract it somewhere separate, then copy ArcScan.exe and README-PORTABLE.txt over the old ones.

  4. Keep ArcScanData and launch

    Leave ArcScanData exactly where it is and launch ArcScan. It upgrades its own database if the new version needs to.

ArcScan upgrades its own database if the new version needs to, so the history, names, notes and settings are all still there. The installed edition’s updater is unchanged: it still checks, verifies the signature, installs and restarts.

Where portable ArcScan will not run.

In each of these cases it says so and stops. It never quietly writes your data somewhere you did not choose.

A folder it cannot write to

Checked by actually writing a file and deleting it again, not by reading a read-only flag: a directory permission, a full disk and a write-protected card all look writable until something is written. Move the folder somewhere writable.

A network location

A \\server\share path, or a mapped drive Windows reports as a network drive. Databases over a network share are not reliable enough to keep a scan history in, so ArcScan refuses rather than risking it. Copy the folder to a local or removable drive.

Inside the ZIP

Windows opens an archive in a temporary folder it deletes without warning, so ArcScan started from inside the ZIP would lose everything it saved. Extract first.

The Microsoft Edge WebView2 Runtime is required, as it is for the installed edition. Current Windows 10 and Windows 11 already have it. The portable ZIP deliberately does not include an installer for it, because portable ArcScan does not install system software, so “no dependencies” is not a claim ArcScan makes. If a USB drive is removed while ArcScan is running, saving will start failing and ArcScan will say so; it does not write your data elsewhere instead. ArcScan is still not code-signed with a paid publisher certificate, so Windows SmartScreen shows an unknown-publisher warning on first launch.

What did not change.

1.8.4 is a distribution release. The scanner is the 1.8.3 scanner.

The installed edition

Same application-data location, same database, same preferences, same migrations, same updater, same window. Installing 1.8.4 over 1.8.x, 1.7.x or 1.6.x keeps everything, exactly as before.

Scanning and discovery

The same read-only ICMP and TCP scanning, the same local mDNS and SSDP discovery with the same URL guard and the same bounds, the same device identification, the same Inventory, Changes and History.

Privacy

Still local only. No account, no cloud service, no telemetry, no analytics. The same two optional outbound requests, still listed in Settings: the update check, and the public-IP lookup that never runs without a press. Read the privacy notes
