ArcScan 1.8.4

What's new in ArcScan 1.8.4

A fresh field session whenever you launch. 1.8.4 adds disposable Windows Portable ZIPs for x64 and ARM64. Extract one, scan and investigate without installing, export anything you want to keep, then close ArcScan. The next Portable launch starts fresh.

Version 1.8.4 · free and open source · Technical release notes on GitHub

Portable for the session, disposable afterwards.

Portable ArcScan is not a persistent USB installation. It is the complete ArcScan experience for a field session, with explicit exports as the boundary between temporary work and records you choose to retain.

One process, one private session

SQLite and the WebView stay together and temporary.

Every Portable process gets a unique directory below <system temp>/ArcScanPortable/sessions/. Its regular arcscan.db keeps Inventory, Changes, History, discovery, devices and ports working normally. Its dedicated WebView/ profile keeps recent targets, theme and preferences isolated too.

Both stores are removed after normal shutdown. If a crash leaves a session behind, a later Portable startup cleans it only after strict namespace, ownership, layout and inactive-lock validation.

Settings tells you the lifetime. About names the edition and architecture, labels session storage as Temporary, and reminds you to export CSV, JSON or XML outside ArcScan before closing.

Installer or portable?

Choose the Installer when ArcScan should remember the machine and its networks. Choose Portable when the session should be isolated and disposable after you export the records you need.

There is no portable macOS build in 1.8.4, and the macOS download is unchanged.

One temporary session, safely owned.

Portable uses the same local SQLite architecture for the session, then removes only the directory it can prove belongs to ArcScan.

The session

Each process gets a unique child of <system temp>/ArcScanPortable/sessions/, containing arcscan.db, WebView/, a validated ownership marker and an active-session lock. Nothing is created beside ArcScan.exe.

The export boundary

CSV, JSON and XML files saved outside the session are yours and survive cleanup. Portable refuses a destination inside its temporary session so an export cannot disappear when ArcScan closes.

Normal and stale cleanup

Normal shutdown closes SQLite and the WebView before removing the owned session. A later startup cleans validated stale sessions left by crashes or locked files while preserving every session whose process is still active.

Said precisely

Cleanup requires a direct session child with a valid matching ArcScan marker, an inactive lock and only the known database, SQLite sidecars and link-free WebView tree. Unknown contents, malformed markers, links, reparse points and arbitrary temp directories are refused. Windows and WebView2 may still keep ordinary operating-system records that ArcScan does not own.

Every process gets its own blank slate.

Installed and Portable can run together, and multiple Portable processes can run together, without sharing a database or WebView profile.

Installed stays Installed

Installed ArcScan keeps its existing application-data database, WebView profile and updater. Portable never reads or writes those locations, even if its temporary session cannot be created.

Portable processes stay separate

Each process receives a different session identifier, SQLite file, WebView profile and active lock. Two copies launched from the same extracted folder can run at the same time without touching each other’s session.

Nothing silently carried over

A Portable launch does not import Installed history or a previous Portable session. Nothing is merged in either direction. Export is the deliberate way to retain or transfer a record.

Updating Portable is intentionally manual.

Portable does not contain the NSIS Installer updater and cannot apply an Installed update. The safe update path respects the disposable session boundary.

  1. Export what matters

    Save CSV, JSON or XML outside the temporary session for anything you want to keep.

  2. Finish and close the session

    Review the remaining results, close ArcScan and let the owned temporary state be cleaned.

  3. Download the latest ZIP

    Choose the Windows Portable asset for the same architecture, x64 or ARM64, from the release page.

  4. Extract and launch

    Start the new ArcScan.exe. It creates a fresh private session; there is no Portable database or profile to copy forward.

latest.json remains an Installed-updater-only manifest. The Installed edition’s updater is unchanged: it still checks, verifies the signature, installs and restarts.

Storage and runtime boundaries.

The executable location and the session location are intentionally separate. A failure in one never authorizes ArcScan to borrow Installed state from the other.

The extracted folder may be read-only

Portable creates no database, profile or persistent data folder beside ArcScan.exe. The extracted folder does not need to be writable. Extract the ZIP before launching so Windows provides the normal executable layout.

System temporary storage is required

If Portable cannot create and lock its private session under the system temporary directory, startup stops with a specific error. It never falls back to Installed AppData, the Installed WebView profile or the executable folder.

Keep USB media connected

Live SQLite and WebView state are on the machine’s temporary volume, not on the USB drive. Windows or the runtime may still need the original executable resources, so leave the media connected until ArcScan closes.

The Microsoft Edge WebView2 Runtime is required, as it is for the installed edition. Current Windows 10 and Windows 11 already have it. The portable ZIP deliberately does not include an installer for it, because portable ArcScan does not install system software, so “no dependencies” is not a claim ArcScan makes. Network-share launch behavior, USB removal, read-only media and endpoint-security interaction remain subject to Windows and WebView2 policy and require representative runtime testing. ArcScan is still not code-signed with a paid publisher certificate, so Windows SmartScreen shows an unknown-publisher warning on first launch.

What did not change.

1.8.4 is a distribution release. The scanner is the 1.8.3 scanner.

The Installed edition and macOS

Same application-data location, same database, same preferences, same migrations, same updater, same window. Installing 1.8.4 over 1.8.x, 1.7.x or 1.6.x keeps everything, exactly as before. macOS remains the same universal DMG, with no Portable edition.

Scanning and discovery

The same read-only ICMP and TCP scanning, the same local mDNS and SSDP discovery with the same URL guard and the same bounds, the same device identification, the same Inventory, Changes and History.

Privacy

Still local only. No account, no cloud service, no telemetry, no analytics. Installed ArcScan keeps its optional update check. Portable updates are manual. The public-IP lookup in both editions never runs without a press. Read the privacy notes
