Privacy

What ArcScan sends, and what it keeps.

ArcScan is a local-first tool, and this page states precisely what that means rather than leaving it as a slogan. It covers the desktop application v1.8.1 and this website.

The short version

Your scan results, device inventory, names and notes never leave your computer. The application makes exactly two kinds of outbound request, both optional and both described below: an update check, and a public IP lookup that is off until you turn it on.

What stays on your computer

Everything ArcScan discovers is written to a SQLite database in your operating system's application data directory. Nothing in it is transmitted anywhere.

  • Scan results: addresses, hostnames, MAC addresses, manufacturers and open services.
  • The device inventory, including first-seen and last-seen dates.
  • Names you give devices, their status, and your notes.
  • Scan history and the comparisons between scans.
  • Your preferences, which are stored separately by the application window.

The database lives at %APPDATA%\com.arcscan.app\arcscan.db on Windows and ~/Library/Application Support/com.arcscan.app/arcscan.db on macOS. It is an ordinary SQLite file: you can copy it, back it up, inspect it or delete it.

Requests the application makes

Update check

On launch, ArcScan asks GitHub whether a newer signed release exists, by requesting the update manifest published with each release. The request carries only what any HTTPS request carries, plus the version being checked. It does not include your scan targets, your results or any identifier.

GitHub receives ordinary request metadata for this, including your IP address, as it would for any file you download from it. You can switch the check off in Settings, Network requests, and ArcScan will then never contact the update feed on its own.

Public IP lookup

ArcScan can tell you the address your internet connection appears from. It never runs on its own. From version 1.8.1 the control sits on the Scan screen, beside the local network, and says Not checked until you press Check. It is not needed for scanning, and it can be switched off entirely in Settings, Network requests, which also lets you forget the current session's answer.

When you do, ArcScan requests https://api64.ipify.org and, if that does not answer, https://icanhazip.com. Those services see your public IP address, because that is what they exist to report back to you. Nothing else is sent: no scan target, no result, no device data, no inventory. The answer is held in memory for the current session only. It is never written to the scan database, never stored as inventory data and never included in an export, and it is forgotten when you close the application or press Forget.

Earlier versions of ArcScan performed this lookup automatically at startup. Version 1.7 changed that, because a network tool should not make an outbound request before you have asked it to do anything, and no version since has looked it up without being asked. Moving the control onto the Scan screen in 1.8.1 did not change that: nothing is looked up at startup, after a scan, when you switch views or on a timer.

Release downloads

When you download an installer or install an update, the file comes from GitHub. GitHub receives the normal request metadata for a download, including your IP address, user agent and the file requested. ArcScan never re-hosts binaries, and this website never serves them itself.

What the scan itself sends, and to whom

A scan sends packets to the addresses you asked it to scan, and to nowhere else. For each address that means one ICMP echo request and a TCP connection attempt on each port the selected profile covers. ArcScan then reads your own computer's ARP table, which is a local operation involving no network traffic of its own.

Devices on the network you scan will see those probes, as they would from any network scanner. Nothing about the scan is reported to the ArcScan project or to anyone else.

What ArcScan never collects

  • No telemetry, usage statistics, crash reports or feature analytics.
  • No account, email address, licence key or device identifier.
  • No upload of scan results, device names, notes, MAC addresses or hostnames.
  • No advertising identifiers, and no third-party SDK of any kind.

This website

The site is static and hosted on GitHub Pages. It sets no cookies, uses no analytics, and loads no fonts, scripts or images from anywhere but its own origin.

It makes one request to api.github.com to read the latest release, so the download cards can show real file sizes and links. That call sends nothing about you beyond the request itself, and the page works fully without it. A Content-Security-Policy header on every page restricts network access to exactly that one host.

GitHub Pages operates the hosting and, like any web host, sees the requests your browser makes. That is outside the ArcScan project's control and is covered by GitHub's privacy statement.

Uninstalling

Uninstalling ArcScan removes the application. It does not delete your database, so your history, device names and notes survive a reinstall or an upgrade. To remove them, delete the database file at the path listed above.

Responsible use

ArcScan performs read-only discovery: it never attempts a password, never sends an exploit, and has no stealth or evasion behaviour. Scan only networks you own or have been authorised to inspect. Scanning a network without permission may be unlawful where you are, whatever tool is used.

Changes to this page

If ArcScan's network behaviour changes, this page changes with it in the same release. The full history is in the repository, and the code that makes every request described here is in the source.
