ArcScan 1.8.7

ArcAtlas handoff only sends what the latest scan actually found.

1.8.7 aligns ArcScan with ArcAtlasNext's presence-aware import workflow. A network inventory can still remember devices that disappeared or whose current presence is unknown, but those historical rows are no longer sent as if the newest scan discovered them.

Present means actionable

Send to ArcAtlas now filters the selected network to rows whose current presence is present. The confirmation tells you how many present devices will be sent and how many missing or unknown historical devices were excluded before transfer.

Historical inventory stays useful

ArcScan still keeps missing and unknown devices in Inventory and history. This release changes the handoff boundary, not the historical record. You can still investigate what used to be on the network without turning that evidence into a current ArcAtlas discovery candidate.

Durable hostnames survive blank observations

A later observation with an empty or whitespace hostname is normalized to no hostname instead of replacing a useful name already learned for the device. Existing databases also repair blank durable hostnames from the newest recorded nonblank observation when one exists. Operator custom names remain untouched and continue to win in the interface.

Infrastructure identity wins over incidental services

Strong manufacturer and model-family evidence for common Synology NAS, Ubiquiti gateway, switch and access-point families, and Dell PowerEdge or iDRAC systems now takes precedence over generic service clues. Conflicting service evidence remains visible instead of being discarded.

Built for the ArcAtlasNext presence workflow

Use ArcScan 1.8.7 or newer for the first production ArcScan to ArcAtlasNext test. It keeps the desktop inventory historical while making the outbound discovery handoff represent the latest compatible scan.
