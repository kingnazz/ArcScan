ArcScan 1.8

What's new in ArcScan 1.8

ArcScan 1.8 turns every scan into a lasting device inventory. Search everything ArcScan has discovered, understand which devices appeared or disappeared, and review network changes when you are ready.

Download ArcScan Back to the ArcScan homepage

Version 1.8.0 · released 3 August 2026 · free and open source · Full technical release notes on GitHub

  • Upgrades over 1.7 without losing anything
  • Windows 10 and 11, macOS 11 or later

Inventory

Every device you have found, in one place.

Earlier versions showed you the devices in the scan you had just run. ArcScan 1.8 adds an Inventory view that holds every device it has ever recorded, so a device you found last month is still there this month, with the name you gave it and the notes you wrote.

  • One row per device, not one per sighting
  • Present, Missing and Unknown
  • Trusted, Unreviewed and Ignored
  • Previous addresses
  • First and last seen
  • Bulk actions
  • CSV, JSON and XML export

Search reaches almost everything ArcScan knows: the name you gave a device, its hostname, its current address, the addresses it used to hold, its MAC address, its manufacturer, the services it is running, the network it belongs to, and the opening of your own notes. Select several devices at once to mark them trusted, mark them unreviewed, ignore them, copy their addresses or export just those rows.

Changes

Changes wait until you have read them.

When a later scan finds something different, ArcScan 1.8 keeps a record of it instead of showing it once and moving on. Each entry stays in the list until you review it, so a change you noticed on a busy Tuesday is still there on Thursday.

  • New devices
  • Returned devices
  • Missing devices
  • Address changes
  • Name changes
  • Opened and closed services

Every entry says what changed, to which device, on which network and when, with the old and new values side by side. Open the device to look properly, trust it, rename it, ignore a device whose changes are never interesting, or simply acknowledge the entry and move on. Nothing is deleted either way, and you can filter the list by kind, by time, by network or by a search term, then export exactly what you are looking at.

Networks

Networks stay separate on their own.

ArcScan keeps devices from different networks separated automatically. You do not have to configure anything, and two networks that happen to use the same addresses never mix their devices, names or notes.

Recognised for you

ArcScan works out which network it is looking at from the network itself, so the laptop you scan at home and the one you scan at work stay apart without being told to.

Names if you want them

Give a network a familiar name such as Home Wi-Fi, Office, Workshop or Guest Network. The name then appears everywhere the network does. A network you have not named simply shows its address range.

Invisible with one network

If you only ever scan one network, the network column and the network filters stay hidden. There is nothing extra to look at and nothing extra to learn.

Presence

Three words, and each one means something exact.

ArcScan scans when you ask it to. It does not watch a network in the background, so it tells you what the most recent completed scan found rather than guessing at what is happening right now.

Present

The latest relevant completed scan saw the device. It answered, and ArcScan recorded everything it could see about it.

Missing

The latest relevant completed scan did not see a device that an earlier compatible scan did see. That earlier scan is what makes the absence meaningful: ArcScan looked in the same place, in the same way, and found nothing.

Unknown

ArcScan does not have enough comparable completed-scan evidence to say either way. This is the honest answer for a network that has only been scanned once, or scanned in a different way.

A scan you stopped early never marks a device Missing. It did not reach every address, so a device it did not see might simply never have been checked. ArcScan keeps everything a stopped scan did find, labels it a partial scan, and leaves presence alone.

Exports

Take the whole picture with you.

Exports follow whatever you are looking at, and each menu says what the file will contain before you choose a format.

The Inventory

Export every device, only the ones you have selected, only the ones your filters have narrowed to, or only one network. Presence and status are written out in words, so a spreadsheet reads the same way the application does.

The Changes list

Export exactly the entries on screen, with the old value, the new value, the review state and the date each one was acknowledged.

Three formats, clear names

CSV for a spreadsheet, JSON for a script and XML where something older needs it. Files are named by date and by what they cover, for example arcscan-inventory-home-wi-fi-2026-08-03.csv.

Upgrading

Install it over 1.7 and carry on.

Install ArcScan 1.8 over ArcScan 1.7 without losing scans, device names, notes, statuses, network names or history.

Inventory is there straight away

ArcScan builds the Inventory from the scans you already have, so it is populated the first time you open the view. There is nothing to import and nothing to wait for.

Changes start from your next scan

The Changes list begins with scans completed after the upgrade, rather than filling up with months of entries you never asked to review. Differences ArcScan found before then are still available through History, in each scan's own comparison.

The upgrade is all or nothing

The database upgrade happens in a single transaction, so an interruption leaves it exactly as it was, and opening the same database again changes nothing.

Unchanged

Still local, and still straightforward.

None of this changes what ArcScan is. It runs on your computer, it keeps what it finds on your computer, and it asks nothing of you beyond a network to scan.

  • No account
  • No cloud database
  • No subscription
  • No device passwords or credentials
  • Scans and inventory stay on your computer
  • The public IP lookup stays optional
  • IPv4 only
  • Port scanning is TCP based
  • Not continuous monitoring
  • Installers are not code signed

Because the installers carry no paid publisher certificate, Windows and macOS both warn the first time you open one. The privacy page states exactly which requests ArcScan makes, and the source is public.
