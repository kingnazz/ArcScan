ArcScan 1.8.1

What's new in ArcScan 1.8.1

A tidying release. ArcScan no longer prints its own name twice at the top of the window, the Scan screen has a clearer order to it, and the optional public IP lookup has moved somewhere you can actually find it. Scanning, the inventory and the changes list work exactly as they did in 1.8.

Version 1.8.1 · released 4 August 2026 · free and open source · Full technical release notes on GitHub

  • Installs over 1.8 with no database change
  • Windows 10 and 11, macOS 11 or later

The window

The name at the top, once.

Earlier versions showed ArcScan twice when you opened the app: once in the title bar that Windows and macOS draw, and again on the row immediately below it, where ArcScan added an icon and its own name. 1.8.1 removes the second one.

  • One title
  • One icon
  • No blank strip left behind
  • Standard window buttons
  • Standard dragging and snapping
  • Standard full screen

The title bar that stays is the one your operating system provides, so the window buttons, dragging, snapping, full screen, keyboard window shortcuts and screen reader support are all the ones you already know. With the duplicate gone, the Scan, Inventory, Changes and History switcher moves up to the start of the first row, which is where it belongs.

Public IP

Your public address, if you ask for it.

ArcScan can tell you the address your internet connection appears from. That has been possible since 1.7, buried at the bottom of Settings. In 1.8.1 it sits on the Scan screen, next to the local network, as a small control that says Not checked until you press Check.

  • Optional
  • Runs only when you press Check
  • Copy the address
  • Check again
  • Kept for the session only
  • Switch it off entirely

It is not part of scanning and scanning does not need it. Nothing is looked up when ArcScan starts, when you open the Scan screen, after a scan finishes, when you switch views, or on any kind of timer. The only thing that asks anybody anything is your press on Check, Refresh or Retry.

The lookup asks api64.ipify.org and, if that does not answer, icanhazip.com. Those are the only two third parties involved, and all they are asked for is the address. Your scan targets, your results, your device names, your MAC addresses and your notes are never sent to them, and the answer is never stored as inventory data: it is held in memory for the session, kept out of the database and out of every export, and forgotten when you close ArcScan.

Refinements

Smaller things, in the places you look most.

None of this changes what ArcScan does. It is spacing, alignment and contrast in the parts of the window you spend your time in.

A clearer order

The window reads top to bottom: the view switcher, then the network you are on, then the scan controls, then the search and results tools. Controls in the same row share a height, so nothing sits half a step out of line with its neighbours.

Counts that stay put

The counts beside Inventory and Changes now sit on a fixed-width badge, so the tabs stop shifting sideways as the numbers grow, and the two badges line up with each other.

Easier to read

Two colours that fell just under the accessibility contrast standard have been darkened: the tab counts, and the Stop button, which is under your pointer for as long as a scan is running. Both now pass in the light theme and the dark one.

Buttons that say what they do

Two different controls above the results table were both called Clear the filter. They are now Clear the search and Clear all filters, and the second one is greyed out when there is nothing to clear.

Nothing lost when narrow

At the smallest supported window size the scan target, the Scan button, the search box and the public IP control are all still reachable. Lower priority details step aside first.

Both themes

Every change above was checked in the light theme and the dark theme, at four window widths, with reduced motion on and with an automated accessibility sweep across every view.

Unchanged

Everything 1.8 does, it still does.

This release deliberately leaves the working parts alone. If you upgraded for the inventory and the changes list, nothing below has moved.

  • The same four views
  • The same scanning behaviour
  • The same present, missing and unknown rules
  • Partial scans still never mark a device missing
  • The same networks and network names
  • The same changes list and review actions
  • The same history and comparisons
  • The same CSV, JSON and XML exports
  • No account, no cloud, no subscription
  • Scans and inventory stay on your computer
  • IPv4 only
  • Installers are not code signed

Because the installers carry no paid publisher certificate, Windows and macOS both warn the first time you open one. The privacy page states exactly which requests ArcScan makes, and the source is public. Coming from 1.7 or earlier? Read what's new in ArcScan 1.8 for the inventory, presence and changes work this release builds on.

Upgrading

Install it over 1.8 and carry on.

Install ArcScan 1.8.1 over 1.8, 1.7 or 1.6 without losing scans, device names, notes, statuses, network names or history.

No database change

Coming from 1.8, there is nothing to migrate at all. Every scan, device, name, note, status, network and date carries straight over. Coming from 1.7 or 1.6, the usual 1.8 upgrade runs once, in place.

Your settings are kept

Theme, density, columns, profiles, ports and limits are all preserved. The public IP lookup is offered by default on a new install; if you turned it off in an earlier version, it stays off and the control does not appear until you turn it back on.

Nothing new to learn

The four views, their keyboard shortcuts and their exports are unchanged. The only thing in a new place is the public IP control, and it explains itself.
