ArcScan 1.8.5

Observed inventory, straight into ArcAtlas.

1.8.5 adds a direct, technician-controlled handoff from ArcScan Inventory to an ArcAtlas Discovery inbox. It removes the export-and-upload step without turning ArcScan into a background agent or changing what Discovery is allowed to do.

Send one network directly from Inventory

Connect ArcScan to a site-scoped ArcAtlas token, choose one network, review the destination and device count, and confirm Send to ArcAtlas. ArcScan sends the same row shape its existing Inventory JSON export already produces. Search text, presence filters, device-type filters and sorting do not silently remove devices from the handoff snapshot.

Nothing is sent when a scan completes. ArcAtlas receives observed evidence in Discovery; it does not silently create or overwrite documented devices.

Connection secrets stay in the right place

Installed ArcScan keeps the connection token in the operating system credential store. Portable keeps it in memory for the current process only. After setup, the full token is never returned to the interface, written to the ArcScan database, placed in a URL or included in diagnostics.

ArcScan accepts HTTPS servers, with plain HTTP limited to local development on loopback. Redirects are refused for bearer-token requests.

Retries do not create accidental duplicate runs

If a request times out or has an uncertain network failure, Retry reuses the same handoff identifier so ArcAtlas can return the already-created run. After a confirmed success, the next deliberate send receives a new identifier and creates a new historical Discovery run.

Small setup improvements

If you paste the full ArcAtlas machine endpoint, ArcScan now normalizes it back to the server URL before validation. The main header also shows the application version, and CI test builds can include the short source commit so it is obvious which binary is running.

The local-first boundary is explicit

ArcScan still has no account, telemetry or automatic scan-data upload. The ArcAtlas handoff is an optional outbound action that occurs only after a technician configures a server and confirms a send. The privacy page documents the exact boundary.
