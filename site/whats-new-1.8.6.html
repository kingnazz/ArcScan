ArcScan 1.8.6

macOS LAN scans keep the devices they actually find.

1.8.6 is a focused reliability release for local scanning on macOS, plus a small ArcAtlas interface cleanup. The important change is underneath the table: ArcScan no longer lets macOS hostname lookups consume the short neighbor-discovery time budget.

Numeric ARP discovery on macOS

ArcScan now reads the macOS/BSD neighbor table with arp -n -a. The numeric flag prevents the operating system from trying to reverse-resolve every address before ArcScan can parse the table. On a populated local network, those lookups could previously run past ArcScan's ARP-read timeout and make the final scan look like only a handful of devices existed.

Numeric ICMP probes too

macOS ping probes now stay numeric, use the platform's per-reply timeout, and stop after the first valid response. That keeps hostname resolution out of the liveness path and makes the scan deadline describe network response time rather than DNS behavior.

The 1.8.5 liveness protections remain

A host that positively answers ICMP or TCP is still retained even if its neighbor-cache entry disappears before enrichment finishes. Legitimate ARP-only devices are still discoverable, while proxy-ARP responses from routers or access points are still filtered rather than turning the whole subnet into false positives.

A cleaner ArcAtlas handoff

Inventory no longer places a separate ArcAtlas button immediately beside Send to ArcAtlas. The send action is now the one clear ArcAtlas control in the toolbar, with connection management available from the send flow when it is needed.

What this release is meant to fix

If Inventory remembered many devices but a fresh macOS local scan finished with only a few rows, 1.8.6 targets that exact failure mode. The inventory remains historical; the scan view still shows only devices evidenced by that scan, but local ARP discovery should no longer disappear because of reverse-DNS stalls.
