# ArcScan website

The static site published to <https://kingnazz.github.io/ArcScan/>. No framework,
no build step and no dependencies: it is four hand-written files plus images, so
what is in the repository is exactly what is served.

## Files

| File | Purpose |
| --- | --- |
| `index.html` | The product page: hero, previews, benefits, change detection, how it works, use cases, comparison, downloads, open source and FAQ. Carries the SEO metadata and the `SoftwareApplication` and `FAQPage` structured data. |
| `privacy.html` | Exactly which requests ArcScan makes, what it stores and what it never collects. |
| `arcscan.v4.css` | The whole stylesheet. The tokens at the top mirror the desktop application's, so the site and the app share one accent and one semantic palette. |
| `arcscan.v4.js` | The mobile menu, the screenshot switcher and the download cards. |
| `assets/shots/` | Product screenshots, generated by `scripts/capture-screenshots.mjs`. |
| `assets/og.v4.png` | The social sharing image, cropped from the inventory screenshot. |
| `robots.txt`, `sitemap.xml` | Crawling and indexing. |

Filenames carry a version (`arcscan.v4.css`) so a cached older stylesheet can
never be paired with newer markup. Rename them when a change would clash.

## Screenshots

Every screenshot is captured from the real v1.7 application, driven in a browser
against its built-in demo network, so an image can never show an older interface
and never contains real client data, hostnames, MAC addresses or public
addresses.

```sh
npm run build
npm run preview &
npm i --no-save playwright sharp
node scripts/capture-screenshots.mjs
```

PNGs are written for compatibility and WebP alongside them for size. The page
references the WebP files; the PNGs are the archive and the source for the social
image.

## Downloads

On load, `arcscan.v4.js` reads
`https://api.github.com/repos/kingnazz/ArcScan/releases/latest` and fills in file
sizes, real asset links and the release date.

| Card | Asset pattern |
| --- | --- |
| Windows x64 | `*x64-setup.exe` |
| Windows ARM64 | `*arm64-setup.exe` |
| macOS universal | `*universal*.dmg` |

The visitor's platform is detected and that card is promoted, but every
alternative stays visible. **The page is fully functional before the script runs
and if it never runs at all**: the markup already points every button at
`releases/latest`, and the request is unauthenticated (60 per hour per IP), so a
rate limit or an outage costs a file size, not a download. That path is asserted
by `scripts/verify-site.mjs`.

## Verification

```sh
cd site && python3 -m http.server 4174 &
npm i --no-save playwright @axe-core/playwright
node scripts/verify-site.mjs
```

Twenty-two checks: no horizontal overflow at nine widths from 320px to 1920px,
the mobile menu staying inside the viewport and reachable by keyboard, the skip
link, heading structure, alt text and intrinsic dimensions, the screenshot
switcher's keyboard support, the download cards and the GitHub API failure path,
platform recommendation, structured data matching the visible version, honest
signing language, no em dashes, and axe-core across WCAG 2.1 and 2.2 AA with no
violations on either page.

## Security and privacy notes

- No backend, no cookies, no analytics, no third-party scripts, no web fonts.
- A `Content-Security-Policy` meta tag limits network access to `api.github.com`
  and blocks inline scripts and styles. `frame-ancestors` is deliberately absent:
  browsers ignore it in a meta tag, so including it would only log an error.
- Installers are linked from GitHub Releases and never re-hosted here, so this
  site cannot serve a tampered file.
- Signing language is deliberately precise. The installers are not
  publisher-signed and the macOS builds are not notarised; only the updater
  artifacts are cryptographically signed. Do not soften that wording unless the
  signing itself changes.

## Run locally

```sh
cd site
python3 -m http.server 4000
# http://localhost:4000
```

## Deploy

Pushing to `main` runs `.github/workflows/pages.yml`, which publishes this folder
to GitHub Pages. Enable it once under Settings, Pages, Source: GitHub Actions.
