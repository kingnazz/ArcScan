ArcScan 1.9.0

Go beyond a device list and see how the network fits together.

1.9 adds optional deep discovery and topology mapping without changing the fast Quick Scan workflow. Technicians can identify Windows systems more precisely, query managed network gear with explicit SNMP credentials, and review evidence-backed links before sending the result to ArcAtlas.

Deep discovery when you need it

Deep Scan inspects services already found by the sweep. With session-only Windows credentials, ArcScan can retrieve exact Windows version/build, hardware manufacturer and model, domain information, system identity, and workstation/server/domain-controller role.

Topology from real network evidence

The new Topology step supports SNMP v2c and v3, LLDP/CDP neighbours, switch forwarding tables, VLANs, link speed and PoE evidence. Confirmed, strong and inferred relationships stay visibly distinct, and ArcScan never tries default SNMP communities on its own.

Port-aware preview

A hierarchical preview shows Internet, the default gateway, switches, infrastructure and endpoints. Switch-side ports come from IF-MIB and forwarding-table evidence, endpoint ports stay unknown unless they were actually advertised, and malformed SNMP labels are rejected instead of displayed as junk.

Conservative Internet and WAN mapping

ArcScan can correlate the scanner's default route with a discovered gateway and show an Internet relationship. An ONT or modem is only inserted when direct neighbour evidence supports it, and ArcScan does not invent an ISP name.

Richer ArcAtlas handoff

Schema v2 handoffs can carry topology connections plus additive Internet/WAN metadata while keeping transport-local inventory IDs intact. Inventory-only sends stay schema v1 for backward compatibility.

Credentials stay session-only

SNMP and Windows credentials are entered by the technician for the current session. They are not written into inventory exports, topology payloads, or ArcAtlas handoffs.
